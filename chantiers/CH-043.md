# CH-043 : la Constellation reprend seule après F5, et la relecture porte sur tout le lot

Constat de l'opérateur (test 35, 02/11) : après F5, la Constellation ne reprend pas seule (il faut cliquer), et la relecture ne couvre que les cuts validés après le F5.

## Cause (ÉTABLI, journal du lot du 02/11 16:23, parties 15 et 16 ; collection `2026-11-02_v4.9.5.35_f5-parties-15-16` de banane-data)
Partie 15, 14:42:45 : le cut 5946 est validé, l'opérateur fait F5 (4,2 s après). Il restait ~41 cuts à valider.
1. ESV rouvre la partie 0 après le F5. `partieChangeeParEsv` (CH-039) prend « page rechargée sur une AUTRE partie » pour la preuve d'une fin de partie normale : le lot est clos à tort (`batch-stopped-at-end` « partie-changee-par-esv »). Le commentaire du code supposait qu'un F5 laisse la même partie : faux.
2. La file tente le retour sur la partie 15 une seconde après le rechargement : le sélecteur de parties n'est pas lisible (`releve-selecteur-parties` « absent » à 14:42:50, « ok » à 14:43:00) → `retour-impossible`, file arrêtée.
3. L'opérateur relance par le bouton : NOUVEAU lot (14:43:01) au cut 5947 avec 0 cut posé ; sa relecture (140 cuts) ne contient que les cuts d'après le F5, pas les 31 de l'ancien lot.
Partie 16, 14:51:22 : lot en pause, « Reprendre » à la main (même lot, `reprise` + `rechargement`) : relecture de 302 cuts, tous ceux du lot. C'est le chemin sain.

## Correction (cette branche)
- `resteDevantPreuve` : la preuve par « page rechargée » n'est retenue que si le compteur du cut validé ne laisse rien devant (rouges derrière le départ déduits ; inconnu = comportement d'avant). Essai rouge puis vert dans `tests/ch039-partie-changee-par-esv.test.cjs` (partie 24 rouverte, compteur 9960 sur 10002 : lot non clos ; compteur « rien devant » : fin de partie conservée).
- `fileRepriseApresRechargement` : le lot de la file en « adaptateur sans réponse » est ré-équipé, la page attendue prête, ESV ramené sur la partie du lot par le lien (6 essais espacés de 3 s, le sélecteur apparaît après le chargement), puis la reprise ordinaire (`reprendreLot`) : même lot, mêmes `processed`, relecture de tous les cuts. Réglage `file.repriseApresRechargement` (défaut vrai), journal `file-reprise-rechargement`, avis « clique sur Reprendre » en cas d'échec. Essais : `tests/file-reprise-rechargement-sw.test.cjs`.
