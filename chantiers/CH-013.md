# CH-013 : file de parties, le bouton (ou l'onglet) dans la maquette de Signal

**Exécutant :** agent (session Claude fille, modèle économique). **Branche :** `chantier/CH-013` partie de `claude/50-test17`. **Coût prévu :** un passage, environ 2 h. **Nature :** maquette HTML seulement, **aucun code d'extension**.

## Contexte
D-244 et D-245 : un bouton dans Orbite qui, activé, enchaîne les parties programmées. L'opérateur choisit **le nombre de parties** ; après chaque partie, **relecture et correction** s'activent ou se désactivent par un bouton ; **pas d'export automatique** ; **rien n'arrête la file à part un bouton d'arrêt**, sauf les cas où continuer est impossible (page qui ne change pas de partie, onglet fermé, ESV muet, lot qui s'arrête sur un refus) : alerte et bilan. Bouton **éteint par défaut**. Premier essai à deux parties avec l'opérateur présent. Bilan par partie. D-245 exige une **maquette cliquable validée par l'opérateur avant le code**. Le 28/10 l'opérateur demande d'ajouter « un bouton ou un onglet dans la maquette actuelle » (lecture de l'intégrateur : la maquette de Signal, `maquettes/ui-5.0/Q-signal.html` avec `Q-R-lisez-moi.md`, `scenes.js`, `commun.css`).

## But
Une maquette cliquable où l'opérateur **voit et essaie** la file de parties dans Signal, sans qu'aucun autre écran ne change d'aspect :
1. **Deux variantes** de placement (un bouton dans l'écran d'accueil d'Orbite, ou un onglet « Parties »), dans la même page ou deux pages, pour qu'il choisisse. Dis laquelle tu recommandes et pourquoi, en une phrase.
2. Les scènes : file éteinte (défaut) ; réglage (nombre de parties, relecture et correction activables) ; en cours (partie 2 sur 3, lot et bilan des parties faites) ; alerte d'arrêt avec bilan ; fin de file. Les chiffres sont inventés et marqués comme tels.
3. Les libellés respectent les règles de sens de Signal : Lancer = lot neuf, Continuer = même lot, Préparer = ne lance rien.

## Contraintes de forme
- **Tu ne changes pas le langage visuel** de Signal : couleurs, symboles, polices et mouvement de `Q-signal.html` restent ceux en place (l'opérateur a rejeté les trois directions de CH-010 le 28/10 : D-257, ne les reprends pas). Tu ajoutes seulement ce qu'il demande, avec les composants déjà dans la maquette.
- Une page autonome (HTML/CSS/JS inline, comme les autres de `maquettes/ui-5.0/`), nommée `S-file-de-parties.html` ; les scènes dans `scenes.js` seulement si c'est la façon des autres maquettes.

## Ce qui est livré
1. `maquettes/ui-5.0/S-file-de-parties.html` (et ce que tu dois modifier de la maquette existante, le moins possible), avec capture en local pour toi seule (aucune capture ne va dans le dépôt).
2. `chantiers/CH-013.rapport.md` : une demi-page : variantes, recommandation, ce qui n'est pas décidé (par exemple le comportement exact après un arrêt dans une partie), ce que la maquette ne montre pas.

## Interdits
- La liste de `CLAUDE.md`. **Rien dans `src/`**, aucun manifeste, aucune version, aucun paquet.
- Aucun nom, code projet ESV, adresse web complète, UUID ni capture dans le dépôt.
- Contrôle local avant chaque poussée : `node tools/scan-identite.cjs` et `node --test tests/scan-identite.test.cjs`.
