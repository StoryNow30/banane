# CH-075 — Typage limité par annotations en commentaires (D-299, étape 1)

Branche : `chantier/CH-075`, partie du tronc `claude/50-test17`. Lire `CLAUDE.md`, `DECISIONS.md` (D-299) et ce ticket en entier avant de commencer.

## But
Un premier module réellement vérifié par TypeScript, sans changer le code exécuté : mieux vaut un module bien typé que 17 000 lignes survolées.

## Périmètre
1. **Inventaire (avant toute annotation)** : repérer le module qui manipule les coordonnées (scène, monde) et ses échanges directs. Proposer ce périmètre à l'intégrateur (`send_message` à `@parent`), avec la liste des fichiers, et attendre sa réponse. Les fichiers interdits aux exécutants (`CLAUDE.md`) et les fichiers gelés restent hors périmètre ; on peut typer leurs appelants, pas les modifier.
2. **Vérification sans génération de code** : `tsconfig.json` (ou `jsconfig.json`) avec `allowJs`, `checkJs`, `noEmit`, `strict`, limité aux fichiers du périmètre ; outil `typescript` en dépendance de développement seulement (rien dans le paquet).
3. **Types distincts** (types « marqués ») pour : mètres, millimètres, repère de scène, repère du monde, numéro de coupe, numéro de partie, identifiant d'opération. Un mélange mètres/millimètres ou scène/monde doit être une erreur du vérificateur. Les déclarer dans un fichier `.d.ts` dédié ou en `@typedef`.
4. **Annotations JSDoc** du périmètre.
5. **Contrôle automatique** : un essai `tests/typage-ch075.test.cjs` qui lance le vérificateur sur le périmètre et échoue sur toute erreur de type ; un essai qui prouve qu'une confusion d'unités est bien rejetée.

## Règles de preuve
- **Commits d'annotations seules** : le code exécuté est identique. Preuve : un outil qui retire les commentaires des fichiers touchés et compare le résultat au tronc (empreintes égales), joint au rapport.
- **Commits de corrections fonctionnelles** (ce que le vérificateur fait découvrir) : toujours séparés, un par défaut, avec un essai rouge puis vert et la comparaison des résultats (`tools/parite-relecture-sw.cjs` et les essais du module ; garde et `parite-l1se-sw --passe` si un module de décision est concerné). Un défaut dans un fichier interdit est signalé à l'intégrateur, pas corrigé.
- Ce que le vérificateur ne voit pas (liste vidée par erreur, mauvaise règle) reste l'affaire des essais de comportement : ne pas le promettre.

## Livraison
Rapport d'une page (`chantiers/CH-075/rapport.md`) : périmètre, types définis, nombre d'erreurs trouvées et leur sort, preuves d'identité du code exécuté, estimation (SUPPOSÉ) pour les modules suivants. Puis `send_message` PRÊT à l'intégrateur. Pas de pull request.
