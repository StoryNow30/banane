# CH-035 : rapport (Aurore entre les parties d'une Constellation)

Branche `chantier/CH-035`. Note de conception : `chantiers/CH-035/CONCEPTION.md`. Tout est derrière `correctionEntreParties.actif`, **éteint** par défaut (`src/settings.js`).

## Ce qui change
- **« Ouvrir » sur un cut d'une autre partie** (réglage allumé) : Écho est mis en pause, la partie change par les boutons d'ESV, Ariane va au cut, puis Écho reprend. Une seule séance Écho couvre toute l'Aurore. Aucune touche, aucune pose, aucune validation, aucun SKIP. Code : `background.js`, `correctionOuvrirAilleurs`.
- **Changement de partie** : le cœur de `fileChangerPartie` est extrait tel quel dans `changerPartieEsv`. La file l'appelle sans aucun changement de comportement. L'Aurore l'appelle avec **le lien du sélecteur seul**, y compris vers la partie +1 (réserve de l'intégrateur du 01/11). Ce que les gestes de la file écrivent dans la partie quittée n'a jamais été relevé sur un vrai ESV.
- **Retour au cut juste après le changement** : il est rejoué tant que la page nouvellement chargée le refuse de façon passagère, jusqu'à 15 s (`gotoBorneMs`). C'est le cas « cache de la partie vide ».
- **Parcours** (`parcours`, pur, `src/correction-liste.js`, version `correction-parcours-1`) : les parties dans l'ordre de la Constellation, puis les cuts par numéro croissant. On finit la partie affichée avant d'en changer. Le cut ouvert n'est jamais proposé comme suivant. La reprise se lit sur les visites d'Écho.
- **Signal (minimal)** : une ligne d'état par partie (à faire, en cours, faite), et le bouton « Ouvrir » actif vers une autre partie. La vue porte `entreParties` et `passage`, selon la convention de CH-036. Réglage éteint : `false` et `null`. L'habillage revient à CH-036.
- **Journal** (donc export Orbite) : `correction-partie` (`schema:1`, version `correction-parcours-1` : de, vers, cible, résultat, motif, mode, tentatives, durée) et `correction-partie-tentative`, une par essai. `correction-ouvrir` porte en plus `changementPartie`.
- **Adaptateur** : aucun patch nécessaire, donc aucun `adaptateur-*.patch`. L'essai navigateur le vérifie : l'adaptateur, le pont et l'observateur de la copie testée sont ceux du dépôt, octet pour octet. `nativeResume` recrée l'observateur après le rechargement que provoque le lien.

## Ce qui n'est pas vérifié
- Le changement de partie **pendant une séance Écho** n'a jamais été vu sur un vrai ESV (SUPPOSÉ). Le lien n'y a jamais été mesuré non plus : la file du 31/10 est passée par les gestes. Si l'opérateur relève un jour que les gestes n'écrivent rien dans la partie quittée, il suffira de rendre `gestes` permis vers la partie +1 dans `correctionOuvrirAilleurs`.
- Le cas du service worker redémarré pendant le changement n'est pas éprouvé en navigateur. La règle de CH-028 (`sw-redemarre` clôt la correction) s'applique, en lecture du code (PROBABLE).
- La garde GCV2 n'a pas été lancée : aucun module de décision n'a été touché, et l'outil demande une base.
- Le `verify` complet revient à l'intégrateur.
- Le réglage reste éteint jusqu'à l'essai de l'opérateur sur un vrai poste.
