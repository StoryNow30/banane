# CH-004 : scan des motifs interdits, motif sensible à la casse

**Exécutant :** cursor. **Branche :** `chantier/CH-004`. **Coût prévu :** un passage court.

## But
`tools/scan-identite.cjs` lit les motifs confidentiels dans `ARIANE_MOTIFS_INTERDITS`, compilés **sans tenir compte de la casse**. Le prénom de l'opérateur, écrit « Mic », attrape alors le mot « mic » qui est une clé de données dans les jeux (des milliers de faux positifs). Il faut un second canal, **sensible à la casse**.

## Ce qui est livré
1. Variable d'environnement `ARIANE_MOTIFS_INTERDITS_CASSE` : mêmes règles que l'existante (expressions séparées par `|`, jamais écrites dans un fichier, illisible = code 2), mais compilée **sans** le drapeau `i`. Les deux variables peuvent coexister ; un motif trouvé par l'une ou l'autre est signalé (`chemin:ligne:confidentiel`).
2. Le message d'avertissement dit laquelle des deux est absente, et le fichier d'en-tête de l'outil décrit les deux.
3. Même ajout dans `tools/hub.cjs` (fonction `verifierMessage`) : la seconde variable y est lue aussi. **Ne touche pas** `hub/telegram/worker.js` (déployé sur un autre service).
4. Essais rouges d'abord puis verts : un motif sensible à la casse trouve « Abc » et pas « abc » ; l'ancien canal reste insensible ; deux variables ensemble ; expression invalide. Les motifs plantés dans les essais sont construits par fragments (aucun nom en clair dans le dépôt).
5. `chantiers/CH-004.rapport.md` : une demi-page.

## Interdits
La liste de `CLAUDE.md`. N'écris jamais la valeur d'un motif confidentiel (même d'exemple réaliste : utilise `secretA|secretB`).

## Critère de fin
`node --test tests/scan-identite.test.cjs tests/hub.test.cjs` verts ; `node tools/scan-identite.cjs` rend 0 sans variable ; branche poussée ; rapport posté sur la PR du chantier.
