# CH-149 — Bouton « Réinitialiser l'extension » dans les Réglages (comme à la première ouverture)

**Tronc** : `ariane6` · **Branche** : `chantier/CH-149` · **Décisions** : D-381.

## 1. Demande de l'opérateur
« *ajouter un bouton dans les paramètres réinitialisant complètement l'extension comme si on l'ouvrait la première fois* ».

## 2. Conception et périmètre
1. **Module pur et testable `src/reinitialisation.js`** (UMD Node + `globalThis.ArianeReinitialisation`) :
   - **`refus(ctx)`** : renvoie `null` si la réinitialisation est permise, ou une raison claire en français si elle doit être refusée. Elle est **refusée** si :
     - un lot Orbite est en cours (`RUNNING`) ou en reprise manuelle (`MANUAL_TAKEOVER`), ou une action du moteur tourne (`busy` ou `task`), ou une reprise / un retour à un cut est en cours ;
     - une Constellation est active (`fileActive`), une 2e passe tourne ou écrit (`passeActive`), ou une relecture est en cours (`relectureEnCours`) ;
     - Écho (`nativeActive`) ou Mes corrections (`manualActive`) est actif ;
     - **un résultat ou une écriture incertaine reste à contrôler dans ESV** (`intent`, `reconcileRequired`, `deferPending`, `applied` non validé, ou intentions de relecture/passe non vides `intentionsEnSuspens > 0`) — on n'efface jamais une alerte de sécurité non acquittée sur ESV ;
     - des écritures de mesure ou la grâce d'observations de fin de lot (`graceObservations === 'en-cours'`) ne sont pas terminées.
     *(Note : un lot `STOPPED`, `PAUSED`, `COMPLETED`, `ERROR` sans écriture incertaine en suspens PEUT être réinitialisé après confirmation explicite — c'est justement l'un des buts d'une remise à zéro complète).*
   - **`executer({ store, storageLocal, storageSession, fermerTelecommande, reinitialiserMemoire })`** :
     1. coupe proprement la télécommande si présente (`fermerTelecommande()`) ;
     2. vide les trois magasins IndexedDB (`await store.clearAll()`, qui vide aussi `indexJournal`) ;
     3. vide intégralement `chrome.storage.local` (`await storageLocal.clear()`) — ce qui supprime l'état, tous les morceaux `banane3Morceaux*`, l'onglet choisi, l'historique des parties, le cache des exports, les instantanés de listes, la Constellation, la passe, la relecture, la télécommande, les préférences d'interface/palette/hauteur, **ainsi que `banane5Poste`** pour que `src/stockage-neuf.js` réaffiche le bandeau de premier lancement ;
     4. vide `chrome.storage.session` si disponible (`await storageSession?.clear?.()`) ;
     5. remet à neuf l'état en mémoire du service worker (`reinitialiserMemoire()`).

2. **Branchement dans le service worker (`background.js`)** :
   - Charger `'src/reinitialisation.js'` dans `importScripts` ;
   - Ajouter deux actions dans `dispatch` (en fin de `dispatch` pour minimiser l'empreinte sur `background.js`) :
     - `'reinitialiser-etat'` → `{ permis: refus === null, refus }` (lu par le panneau pour activer/désactiver le bouton et afficher la raison si grisé) ;
     - `'reinitialiser-extension'` → exige `args?.confirme === true` (sinon lève une erreur), revérifie `refus`, exécute `ArianeReinitialisation.executer(...)`, remet à zéro en mémoire `selectedTab = null`, `engine = new BananeEngine3.Engine(adapter, store)` (avec ses branchements ou réinitialisation propre de `engine.s` vierge `schemaVersion: 4`, `mode: 'observation'`, `collection: 'IDLE'`, `notice: 'Prêt. Sélectionne un onglet ESV.'`, `enBase.clear()`, `store.connus = new Map()`, `store.index = new Set()`), vide `finsLot`, `fileP.etat = null`, `passeDiff`, `relecture.passe = null`, `ajEssai = null`, `bandeau.on = false`, `b1.repere = null`, `gsOmbre`, `voieSure`, désactive le lanceur/bandeau ESV (`syncLauncher()`), réinitialise `telecommande`, et renvoie `{ ok: true }`.
   - Attention : ne pas recréer `engine` si des fermetures enveloppent `engine.analyze` / `engine.event` / `engine.save` ! Il est **beaucoup plus sûr et propre** de réinitialiser `engine.s` en place à sa structure vierge d'origine (exactement celle du constructeur de `Engine` dans `src/engine.js` l. 21–23), `engine.enBase.clear()`, `engine.fenetre = null`, `store.connus = new Map()`, `store.index = new Set()` !

3. **Interface utilisateur (`panel.html`, `src/ui5.js`, `src/signal-rendu.js`)** :
   - Fonctionne automatiquement dans **Glacier**, dans **Mix** (`src/mix-rendu.js` hérite de `feuilleHtml` de `src/signal-rendu.js` !) et sur la **Télécommande** (`telecommande/` utilise `signal-rendu.js`) !
   - Au bas de `feuilleHtml` (`src/signal-rendu.js` l. 631, dans `.sg-bas`), ajouter une `.sg-danger-zone` dédiée à la réinitialisation complète :
     - État normal : texte explicatif court (*« Remise à zéro complète : efface le cache, l’historique et tous les réglages locaux, comme à la première ouverture. »* + raison du refus si indisponible) et bouton `data-act="sg:reinit-demander"` (`disabled` si `!snap.reinit?.actif`) libellé `Réinitialiser l’extension…`.
     - État confirmation (tenu dans l'état UI de `ui5.js` / `signal-rendu.js`, **sans `window.confirm` bloquant** pour fonctionner aussi sur la Télécommande et dans tous les essais headless !) : quand l'opérateur clique sur `Réinitialiser l’extension…`, afficher à la place dans la même zone deux boutons : `Confirmer la remise à zéro` (`data-act="sg:reinit-confirmer"`) et `Annuler` (`data-act="sg:reinit-annuler"`).
     - Après succès de `reinitialiser-extension` (`{ confirme: true }`), recharger le panneau (`location.reload()`) : le panneau se rouvre en Glacier sombre avec le bandeau jaune « Réglages neufs sur ce poste » (`src/stockage-neuf.js`) !
