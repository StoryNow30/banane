# CH-038 : rapport (lot arrêté au cut 115 après un déplacement de vue)

Branche `chantier/CH-038` (partie de `claude/50-test17`, 4.9.5.33). Note de cause : `chantiers/CH-038/NOTE.md`. Qualifications : ÉTABLI = mesuré, PROBABLE, SUPPOSÉ.

## Cause (ÉTABLI, sauf mention)
- Le second glisser est celui d'`apply`. Le pré-vol est un essai sans pose ; la pose refait le geste. Ce n'est pas un défaut.
- Les deux rails étaient posés quand l'erreur est partie. Elle vient de la remise à la fin d'`apply` (`remettreVue` → `select`). Preuves : trois `railPairSeen` espacés de 12,03 s, 3 × `attenteMs`, durée de 37,9 s.
- `select` exige « rail dans la vue ». Le bouton centre la vue sur le rail (NDC 0,0 dans la caméra de capture), et la cible est à 200,1 mm, soit NDC −1,001 (vue de 778 px à 0,514 mm/px). Le rail posé à la cible ne peut donc pas être dans la vue habituelle. PROBABLE : ESV recentre sur la position d'origine du rail.
- Le pré-vol ne pose rien : sa remise réussit toujours, donc il ne pouvait pas voir ce cas.
- La remise est notée « inconnu » parce que le message n'était pas reconnu par `detailRemise`.

## Livré
1. **Patch d'adaptateur** `chantiers/CH-038/adaptateur-remise-vue.patch` (non appliqué ; `git apply --check` vert à la racine) :
   - la vue habituelle de chaque côté est mémorisée avant les gestes (`etat.vues`) ;
   - `recentrerRemise` : bouton pressé 3 fois au plus. Réussite si la caméra est stable ET revenue à la vue habituelle (1 mm, `remiseTolerance` d'échelle) OU si le rail est dans la vue. Sur un délai, elle ne lève plus : elle rend `ok:false` (`recentrage-impossible`) ;
   - `apply` lève alors « Vue ESV non restituée … (échelle à x %, le bouton du rail droit n'a ramené ni la vue habituelle ni le rail dans la vue en n pressions) : les deux rails sont posés, rien n'est validé » ;
   - le pré-vol (`amenerDansLaVue`) exige le retour à la vue habituelle (`vue-habituelle-non-revenue` sinon, et le cut reste différé) ;
   - le rapport de remise porte `vueHabituelle`, `railDansVue` et `pressions`.
2. **Service worker** (`background.js`, `src/deplacement-vue.js`) : sur une erreur de pose avec plan, ESV est relu. Rails identiques → `ecriture:'aucune'` ; différents → `'faite'` ; illisible → `'inconnue'`. Le champ va dans `deplacer-vue`, et la raison est ajoutée au message du lot (Signal, `batch-error`). « Vue ESV non recentrée » pendant une pose est classée `echec` (`recentrage-impossible`). Aucune commande nouvelle, jamais de SKIP ni de validation.
3. **Maquette** : option `recentrage` (`rail` par défaut et inchangé ; `origine` = comportement d'ESV SUPPOSÉ ; `ailleurs` = panne simulée pour un rail déjà posé).
4. Le réglage `deplacerVue` reste **allumé** (D-268) : la cause se corrige.

## Ce que la maquette ne prouve pas
