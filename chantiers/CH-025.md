# CH-025 : montrer la file de parties dans l'interface Signal

**Exécutant :** agent (session fille). **Branche :** `chantier/CH-025`, partie du tronc `claude/50-test17`. **Périmètre :** `src/ui5.js`, `src/signal-rendu.js`, `panel-signal.css`, `panel-ui5.css`, essais ; pas de nouvelle fonction côté service worker.

## Constat (ÉTABLI, capture de l'opérateur, test 25)
L'opérateur ouvre la 4.9.5.25 : Signal est la seule présentation (`src/ui5.js` lit le DOM du panneau classique après chaque rendu et dessine son propre habillage). La carte `#file-parties` (panel.html, logique `afficherFile` et boutons `file-principal`, `file-secondaire`, `file-n` dans panel.js ; vue `fileParties` du service worker, allumée par `src/settings.js` `file.actif`) existe dans le DOM mais **Signal ne la lit pas et ne la dessine pas** : l'opérateur ne voit aucun réglage ni bouton avant « Démarrer le lot ». La fonction marche côté service worker mais n'a aucune porte d'entrée visible. L'opérateur s'attendait à un bouton dédié, à régler avant le lancement.

## But
Dans l'écran « prêt » d'Orbite de Signal, un point d'entrée discret et clair « File de parties » : choisir le nombre de parties (1, 2, 3, 4, 5, 8 ; le premier essai est à 2), « Préparer » (ne lance rien), « Lancer », « Arrêter la file » ; pendant la file : état (« partie 1 sur 2 », phase : lot, deuxième passe, relecture et correction, changement de partie), alerte d'arrêt, bilan par partie, fin. Rien d'automatique sur l'export.

Référence visuelle validée par l'opérateur : `maquettes/ui-5.0/S-file-de-parties.html`, variante A (D-261). La maquette de l'interface actuelle `Q-signal.html` reste la référence de style (D-271 : l'opérateur reste sur l'actuelle, aucune série Q2 à Q5 ni b2/b3). Reprends les dessins et couleurs de l'actuelle.
